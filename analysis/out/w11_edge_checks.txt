W11 B3 leak audit, hESC TFs+500, hero config (val_frac 0.1, split_seed 0). Line numbers refer to src/pair_gnn.py.

(i) validation positives are never in the message-passing graph while validation is scored
  CONFIRMED for the pair itself: graph edges come only from training rows (L200-203: pos_rows = tri positives; evaluate() L345-348 uses full_graph() with no validation edge); assert uid[val rows] == -1 for all 2068 validation rows; 0 validation pairs duplicate a training pair in the same direction.
  REFUTED in the reverse direction: the graph is undirected, so a validation pair (t,g) whose reverse (g,t) is a training positive is scored through its own edge. 6 of 2068 validation pairs (1 of 303 positives).

(ii) test pairs are never in any training graph
  Same-direction: CONFIRMED, 0 of 7142 test pairs appear in Train_set (any label).
  Reverse direction: REFUTED, 28 of 7142 test pairs (7 of 1061 positives) have the undirected edge in the graph built from the validation-split training rows; with the refit graph (all training rows, val_frac 0) the count is 30 (task A, analysis/out/w11_reverse_leak.txt).
  Training itself never uses test rows: prepare() reads Test_set only into D["te"] (L176, protocol random leaves it untouched); fit() only reads te at evaluate()/final scoring (L345-350, L410).

(iv) degree/popularity quantities use training rows only
  CONFIRMED by code: DEG/NC/NEG (L287-293, used only with --rank_w > 0, off in the hero) are built from yt, tft, pos_t = tr[tri] (L288-293); tri excludes the validation rows (assert tri & vai = {}) and the test file is never indexed.
  Check: recomputed in-degree from tr[tri] sums to 2727 positives, below the 3030 of all Train_set rows, so validation positives are excluded; test positives are never in either.
  scalars.get (PANDA/contrast; off in the hero) also starts from trn = tr.iloc[tri] (analysis/scalars.py L69-70). The GCN/SAGE degree normalisation uses the same graph (training edges only).
  Caveat, not a leak: standardised expression x (L178), and the co-expression kNN graph (L72, npanda only) use all cells but no labels.

(iii) Geneformer embeddings use no labels
  CONFIRMED by code reading: pair_gnn L186 calls Trainer._get_embeddings (src/train.py L41-57), which reads scFM/Geneformer/<cell>_500_gene_embeddings.csv and maps rows to genes through <cell>_500.csv (gene -> Ensembl id).
  The loader takes no label, split or graph argument and builds one 896-d vector per gene (zeros when the gene is missing). The embeddings are precomputed files (pretrained Geneformer on the expression data);
  the generation script is not in the repository, so that last step is taken from the file provenance and cannot be audited from here.
